# How to use a template to initialize a git project

If the project is (almost) empty (no files, or perhaps just some initial `README.md`/`SPEC.md`/`TODO.md`, no or very few commits), first initialize it from a template. Use organisation/user templates if you know them, otherwise good starters are:

* Python projects: https://github.com/lsimons/lsimons-template-py
* TypeScript projects: https://github.com/lsimons/lsimons-template-ts
* Go projects: https://github.com/lsimons/lsimons-template-go
* Rust projects: https://github.com/lsimons/lsimons-template-rs
* Documentation projects: https://github.com/lsimons/lsimons-template-doc
* Monorepo / multilanguage projects: https://github.com/lsimons/lsimons-template-mono

If you use one of these starters, follow the *Using This Template* section from the template its `README.md`. This helps to fill in placeholder values. For other starters, follow their instructions or if there are no instructions, handle renames/placeholders manually.

If it is unclear which template is the best fit, ask the user.

These templates are set up to use the open source Apache License, v2.0. Unless the user has already specified that's the license they want, remove the initial `LICENSE`, and also remove its mention from the `README.md`.

These templates are set up with an initial README.md. You should edit this README so it is no longer about the template, but about the new project instead, removing template details.
